# CLAUDE.md

Курсовая работа (МАИ): собрать данные об открытых курсах из LMS МАИ (lms.mai.ru, Moodle)
в базу данных и подключить ИИ-агента, который отвечает на вопросы о курсах, опираясь на эту базу.

  и объясняй, куда его вставить.

  Хорошо работают сырые HTTP-запросы и ответы, схемы «кто → кому», эксперименты
  «сломай и посмотри».
- Предпочитай короткий и понятный код вместо «промышленного» (без лишних классов,
  слоёв абстракции, ретраев, CLI), пока я сам не попрошу усложнить.

## Ключевые решения и почему

1. **Данные берём через официальный REST API Moodle, а не парсингом HTML.**
   `robots.txt` lms.mai.ru запрещает автоматический обход страниц; API отдаёт чистый JSON,
   работает под моей учётной записью и с моими правами. Это же — раздел курсовой
   про этические и правовые аспекты. HTML-парсинг только как запасной вариант,
   и не обходом сайта, а разбором страниц, сохранённых вручную из браузера.
2. **Сертификат.** На моём компьютере `requests` падал с `CERTIFICATE_VERIFY_FAILED:
   self-signed certificate in certificate chain` (корень Минцифры или антивирус,
   которых нет в `certifi`). Решено через `truststore`:
   `import truststore; truststore.inject_into_ssl()` в начале скрипта, **до** `import requests`.
   **Никогда не предлагать `verify=False` или `http://`.**
3. **Секреты.** Токен лежит в `.env` (`LMS_TOKEN=...`), читается через `python-dotenv`.
   Не печатать токен и пароль в консоль, не коммитить, не просить прислать в чат.
   Ответы API с личными данными (имя, userid) не сохранять в репозиторий, только в `data/raw/`.

## Что сделано

- `step1_token.py` — получает токен: `POST https://lms.mai.ru/login/token.php`
  с `username`, `password` (через `getpass`), `service=moodle_mobile_app`. **Работает**,
  токен получен и сохранён в `.env`.
- `step2_site_info.py` — первый вызов API: `POST https://lms.mai.ru/webservice/rest/server.php`
  с `wstoken`, `wsfunction=core_webservice_get_site_info`, `moodlewsrestformat=json`.
  Печатает сайт, пользователя, версию Moodle и проверяет, есть ли в списке `functions`
  `core_course_get_categories` и `core_course_get_courses_by_field`. **Работает.**
- Оба файла подробно разобраны: путь запроса (DNS → TCP → TLS), кодирование тела
  `x-www-form-urlencoded`, объект `Response`, что делает Moodle на сервере
  (проверка токена → выполнение от имени пользователя → проверка права на функцию →
  проверка параметров → фильтрация ответа), GET vs POST (ответ приходит всегда).
- `step3_categories.py` — функция `call_api(function, **params)` (`Session`, `timeout=30`,
  проверка `exception` → `RuntimeError`). Получает категории (`core_course_get_categories`),
  сохраняет в `data/raw/categories.json`, считает статистику и строит словарь
  `full_names: id → «Институт / Кафедра / 5 курс»` по полю `path`. **Работает.**
  Разобраны: Session vs `requests.post` (keep-alive, без повторных TCP/TLS-рукопожатий),
  зачем `timeout`, `encoding='utf-8'` + `ensure_ascii=False`, поля категории.

### Что узнали о данных LMS МАИ

- 566 категорий, 33 верхнего уровня, 449 категорий с курсами, сумма `coursecount` = 13 114
  (верхняя оценка: вероятно, включает скрытые курсы).
- Верхний уровень неоднороден: институты №1–14, филиалы, доп. образование (ДПО,
  повышение квалификации, переподготовка, English courses), служебные разделы
  («Разделы сайта», «Приёмная комиссия», «УМО ОД»). Открытые курсы скорее всего в доп. образовании —
  проверить по `enrollmentmethods` на шаге 2.
- Названия неуникальны («5 курс»), поэтому храним полное имя по `path`.
- Данные грязные (пример: несовпадающие кавычки в названии Института №5).
- API отдаёт категории в порядке `id`, а не как на сайте (там порядок по `sortorder`).

### Что важно помнить про Moodle API

- Адрес у всех функций один, действие задаёт `wsfunction`.
- Ошибки приходят с HTTP **200**, внутри JSON: `{"exception": ..., "errorcode": ..., "message": ...}`.
  Проверять наличие ключа `exception`, а не `status_code`.
- Некоторые функции возвращают список, а не словарь (`core_course_get_categories`).
- Вложенные параметры передаются как `criteria[0][key]=...`.
- Всегда ставить `timeout`; для серии запросов использовать `requests.Session()`.
- Состав полей зависит от прав: студенту не приходят `idnumber`, `visible`, `timemodified`
  и т. п. (это фильтрация ответа на сервере).
- Категория: `parent` = id родителя (0 — верхний уровень), `path` = `/191/200/420`
  (цепочка id от корня), `depth` = уровень, `coursecount` = курсы только в этой категории,
  без подкатегорий.
